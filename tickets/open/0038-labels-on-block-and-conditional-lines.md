title: A label on a block or conditional line is silently dropped
priority: medium

## Summary

```
ship_gfx:       rept 8,phase
                SHIP_ART phase
                endr
```

assembles without complaint and leaves `ship_gfx` undefined. So does a label on
`DUP`, on `IF`/`IFN`/`IFDEF`/`IFNDEF`, on `ELSE`/`ELSEIF`/`ENDIF`, and on
`ENDR`/`EDUP`. sjasmplus defines the label at the location counter and then
processes the directive, which is what a table generated by a `REPT` needs: the
label is the only way to name what the repetition produced.

The silence is the sharp end of it. Nothing is reported where the label was
written; the error arrives later and somewhere else, as `undefined symbol` at
the first use, which for a table of graphics is a different file.

Found while writing `games/scroller`, which now puts the label on its own line
above every `rept` — twice, having diagnosed it wrongly the first time as
local labels not surviving a `rept` body. They survive it fine.

## Acceptance criteria

- [ ] `label: rept n` defines `label` at the address the repetition starts at,
      and the same for `DUP`
- [ ] `label: if cond` defines `label`, and so do `ELSE`, `ELSEIF` and `ENDIF`
- [ ] `label: endr` and `label: edup` define `label` after the block
- [ ] A label on a line inside a skipped `IF` is *not* defined, as now
- [ ] `name MACRO p,q` still reads `name` as the macro's name and not as a
      label — that spelling is deliberate and is tested
- [ ] A local label works in each of the above positions, scoped to the global
      label above it

## Notes

Two code paths, one cause: a statement whose directive is handled early never
reaches the label definition in `Assembler::statement`
(`crates/rkw-asm/src/assemble.rs`, the `define_label` call after the constant
check).

- `Assembler::run` takes `"macro" | "rept" | "dup"` and `"endm" | "endr" |
  "edup"` before `statement` is ever called, because a block is collected as a
  unit whether or not it is being assembled.
- `Assembler::statement` returns early for the conditionals, above the label
  code, because an `IF` has to be read even inside a block that is being
  skipped.

Both are right about what they are doing and wrong about what they skip on the
way. The fix is to define the label first — while `state.active()`, so a label
inside a skipped conditional still goes nowhere — and then dispatch, rather
than to add a label case to each early path.

Watch the address a label on `ENDR` takes: after the repetition, not before it,
which means it cannot be defined until the block has been walked.
